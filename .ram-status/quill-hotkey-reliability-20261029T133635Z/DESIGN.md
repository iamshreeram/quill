# Goal
Permanent fix for two user-reported hotkey problems on macOS (quill 0.7.x, branch fix/hotkey-reliability off main 639a68a; PR only, NEVER push main - pushing main auto-releases):
 P1 "Quill failed" banners (sometimes) and "not copying to clipboard".
 P2 no feedback at all when a run succeeds, falls back to offline or finds nothing, plus the log is overwritten on every run so failures vanish.

# Evidence (measured on the user's Mac, 2026-10-29)
E1 One press of cmd+shift+c started ~24 `hotkey.sh` runs at once: history.jsonl shows 7 + 17 AI runs in two consecutive seconds on the same 632-char input. Cause: macOS key repeat (user has KeyRepeat=2, InitialKeyRepeat=15 => ~33 repeats/s after 225 ms) and skhd re-fires a held chord. Each run does Edit>Copy (which puts the ORIGINAL text back on the clipboard) then quill --now then writes its result: runs overwrite each other; the final clipboard is whichever finished last. 24 AI calls per press also risks gateway rate limits.
E2 `quill --now` (src/main.rs transform_clipboard ~124-185) exits 1 (=> old hotkey.sh shows "Quill failed") in auto mode ONLY for: "clipboard is empty or has no text" and "failed to write result to clipboard" (an AI error falls back to offline and exits 0). pbcopy leaves an empty-clipboard window: with 3 concurrent writers and 2 readers, 114 of 231 pbpaste reads were empty. Electron apps (Slack, VS Code) can also fill the pasteboard late; hotkey.sh waits only 0.1 s.
E3 quill.log is written with `2>` so only the last run survives (the failing runs' messages were lost). No banner on success/fallback/no-change, so the user pastes too early and sees the original text.

# Changes
C1 hotkey.sh (render_hotkey_script in src/modules/setup.rs; signature `(binary: &str, log_path: &str) -> String` unchanged) gets:
  a) SINGLE INSTANCE LOCK. LOCKDIR="$(dirname <log>)/.hotkey.lock" (inside the 0700 config dir, never /tmp). Acquire with atomic `mkdir`; the winner writes its pid to "$LOCKDIR/pid" and ONLY THEN installs `trap 'rm -rf "$LOCKDIR"' EXIT` plus `trap 'exit 130' INT` and `trap 'exit 143' TERM HUP` (a loser must never delete the winner's lock). A loser exits 0 silently (no banner, no log line, no Edit>Copy, no quill). Stale takeover: if the lock exists and its pid file names a process that is not alive (`kill -0` fails) it is stale; if the pid file is missing/empty (winner between mkdir and the pid write) it is treated as HELD unless the lock directory is older than 5 minutes (`find "$LOCKDIR" -maxdepth 0 -mmin +5`); a lock whose pid is alive but older than 5 minutes is also taken over (hung run; quill's own request timeout is shorter). Takeover = `rm -rf` + one more `mkdir`; if that mkdir loses a race, exit 0 silently.
  b) The copy step, permission classification and stop_with() from PR #2 stay exactly as they are, but now run AFTER the lock is held, so a permission failure also releases the lock (EXIT trap).
  c) quill stderr goes to a private temp file inside the lock dir (`RUNLOG=$(mktemp "$LOCKDIR/run.XXXXXX")`), the run's rc is captured (`if quill --now 2>"$RUNLOG"; then rc=0; else rc=$?; fi`), and the result is APPENDED to the real log as one block: a header line `YYYY-MM-DD HH:MM:SS run pid=<pid> rc=<rc>` followed by the run's stderr. The stop_with() permission message is appended the same way (with the same header style). After appending, trim: if the log is larger than 100000 bytes keep only its last 400 lines (done while holding the lock, `tail -n 400 log > log.tmp && mv log.tmp log`; private umask 077 keeps 0600).
  d) BANNERS (all through the existing notify() which passes text as an osascript ARGUMENT, so log-derived text is data, never code). Classify by the run's stderr/rc, checked in this order:
     rc != 0            -> "Quill failed: <last non-empty stderr line without a leading '[quill] ', cut to 160 chars>. See ~/.config/quill/quill.log"   (if stderr is empty: "Quill failed (exit <rc>). See ~/.config/quill/quill.log")
     stderr has "falling back to offline grammar mode":
         reason = text between "AI request failed (" and "); falling back" (first match, cut to 120 chars)
         and stderr has "no changes" -> "Quill: AI failed (<reason>). Offline grammar found nothing to fix; clipboard left as is."
         else                       -> "Quill: AI failed (<reason>); used offline grammar fixes. Result is on the clipboard - paste with Cmd+V."
     stderr has "[quill] no changes"                 -> "Quill: no changes found; clipboard left as is."
     stderr has "done (offline grammar mode)"        -> "Quill: offline grammar fixes applied. Result is on the clipboard - paste with Cmd+V."
     stderr has "[quill] done"                       -> "Quill: result is on the clipboard - paste with Cmd+V."
     otherwise (rc 0, unknown output)                -> "Quill: finished. See ~/.config/quill/quill.log"
  e) keep: `#!/bin/sh`, `umask 077`, shell_quote() on every path/message, valid POSIX sh with a space+apostrophe in paths, the `quill.log` text, `sleep 0.1` after the copy.
C2 src/modules/clipboard.rs: add `fn retry_nonempty<F: FnMut() -> Option<String>>(f: F, attempts: u32, delay: std::time::Duration) -> Option<String>` (calls f up to `attempts` times, sleeping `delay` between tries (not after the last), returns the first Some) and `pub fn get_text_retrying() -> Option<String>` = retry_nonempty(get_text, 4, 50 ms) (so an empty read is retried for ~150 ms in total). Also `set_text_retrying(text) -> bool` (3 attempts, 50 ms, true as soon as set_text returns true). Platform-neutral (all three get_text backends). src/main.rs transform_clipboard uses get_text_retrying/set_text_retrying (both write sites). No other behaviour change: same messages, same exit codes. `--stdin` is untouched.
C3 README: macOS hotkey section documents the lock (holding or repeating the shortcut starts one run), the banners (exact texts), the appended log with its 100 KB / 400-line trim, the clipboard retry, and the known limit that a slow app can still leave the OLD clipboard text for quill (0.1 s wait; copy manually and press the shortcut again). Update the "Hotkey does nothing" troubleshooting bullet.
Non-goals: no sentinel clipboard trick (it would break the copy-manually-then-press workflow), no change of `quill status`, no new CLI flags, no change to exit codes or to any quill stderr text (hotkey.sh PARSES the existing lines: "processing N chars...", "done", "done (offline grammar mode)", "no changes", "AI request failed (<e>); falling back to offline grammar mode.").

# REVISION 2 AMENDMENTS (supersede conflicting text above)
A1 (C1, C2) LOCK, replaces C1(a) stale rules. Functions in hotkey.sh (POSIX sh):
  owner_alive PID: `kill -0 PID` must succeed AND `ps -p PID -o command=` must be empty (cannot tell => alive) or contain `hotkey.sh` (guards against PID reuse by an unrelated process); otherwise dead.
  try_acquire: `mkdir "$LOCKDIR"` then write `$$` to "$LOCKDIR/pid"; success => return 0.
  lock_is_stale (ONLY called while holding the guard): pid file non-empty => stale iff NOT owner_alive; pid file missing/empty => stale iff the lock dir is older than 5 minutes (`find "$LOCKDIR" -maxdepth 0 -mmin +5`). A lock whose owner is ALIVE is NEVER reclaimed, whatever its age (no age takeover of live owners; a slow run up to timeout_secs=600 is respected; manual recovery for a pathological case = remove ~/.config/quill/.hotkey.lock, documented in README).
  acquire: `try_acquire && return 0`; else take the reclaim GUARD with `mkdir "$LOCKDIR.guard"` - if that fails, someone else is reclaiming (or a guard was left by a crash): if the guard dir is older than 1 minute (`find ... -mmin +1`) `rmdir` it, in every case return 1 (this invocation exits silently; the next trigger recovers). With the guard held: re-read the owner NOW; if lock_is_stale then `rm -rf "$LOCKDIR"; try_acquire; rc=$?` else rc=1; always `rmdir "$LOCKDIR.guard"`; return rc. A failed acquisition never removes anything it did not itself prove stale while holding the guard.
  The EXIT/INT/TERM/HUP traps are installed only after try_acquire succeeded and remove only "$LOCKDIR" (a loser never installs them). rm -rf of the lock dir also removes RUNLOG/trim temp files that live inside it.
  Losers exit 0 silently (no banner/log/copy/quill).

# REVISION 3 AMENDMENTS (supersede A1, parts of A2/A3/A5/A6 and C1(a) completely)
B1 LOCK = KERNEL FLOCK (replaces A1 entirely; NO mkdir lock, NO guard, NO pid file, NO stale/age rules, NO owner_alive). At the top of hotkey.sh, after `umask 077`:
   LOCKFILE="$(dirname <log>)/.hotkey.lock"  (a regular, empty file in the 0700 config dir, never /tmp)
   if [ -L "$LOCKFILE" ] || { [ -e "$LOCKFILE" ] && [ ! -f "$LOCKFILE" ]; }  => notify "Quill: the lock file is a symlink or not a regular file: <LOCKFILE>. Remove it and try again." and exit 1.
   LOCKING=1; command -v perl >/dev/null 2>&1 || LOCKING=0;  ( : 9>>"$LOCKFILE" ) 2>/dev/null || LOCKING=0   (cannot create/open the file => degrade, never abort).
   if [ "$LOCKING" = 1 ]; then exec 9>>"$LOCKFILE"; perl -e 'use Fcntl qw(:flock); open(my $fh, ">&=", 9) or exit 2; exit(flock($fh, LOCK_EX | LOCK_NB) ? 0 : 1)'; case $? in 0) ;; 1) exit 0 ;; *) LOCKING=0 ;; esac; fi
   Semantics: flock locks belong to the open file description, which the shell keeps open on fd 9 for its whole life; perl only inherits it. The kernel drops the lock the instant the owning shell dies for ANY reason (exit, signal, SIGKILL, crash), so there is nothing to recover and a live owner is never taken over. A loser (rc 1) exits 0 silently: no banner, no log, no Edit>Copy, no quill. If locking is unavailable (no perl / cannot open the file / perl error) the script DEGRADES to today's behaviour (runs without a lock) and appends one extra line `[quill] warning: single-instance lock unavailable` to the run's block.
   EVERY child the script starts (osascript x3, quill, mktemp is fine) is started with `9>&-` so no child can inherit and prolong the lock (a hung osascript/quill that outlives the shell cannot keep it, and the lock never outlives the shell's own life except through fd 9).

Fix them and try again."; exit 1; }` BEFORE the copy step. # REVISION 4 AMENDMENT (supersedes the B1 'EVERY child ... 9>&-' paragraph and the B4 SIGKILL-owner and children-do-not-inherit tests)
B5 (C7) fd 9 is KEPT open in the clipboard-mutating foreground children: the Edit>Copy `osascript` and `quill --now` inherit the lock's open file description (no `9>&-` on them). Only notification-only children (the `notify` osascript, helpers like sed/grep/tail/date/mktemp) are started with `9>&-`. Consequence: the lock is held until the LAST process that can still touch the clipboard has exited, even when the shell itself is killed (SIGKILL leaves the foreground quill running; it keeps the lock; contenders skip silently until it ends). Release = the last participating process closes the shared description; nothing needs recovering.
B5 TESTS (replace the two superseded tests): (a) kill the script shell with SIGKILL while its BLOCK-mode fake quill is alive => a new invocation silently skips (no copy, no quill call, no banner); then release and reap the old fake quill => the NEXT invocation acquires and runs normally (quill call count +1); (b) a notify-only child that outlives the script must NOT hold the lock: the fake osascript's `display notification` branch starts `sleep 5 &` in the background; after the script exits the NEXT invocation still acquires. Both on macOS and Linux (bounded waits).
